## 버그 보고

### 심각도

**P0 - 치명적**
- 서비스 완전히 중단
- 사용자 데이터 유출 가능성
- 보안 취약점

**P1 - 높은 우선순위**
- 주요 기능 작동 안함
- 많은 사용자 영향
- 우회 방법 존재

**P2 - 중간 우선순위**
- 부가 기능 문제
- 일부 사용자 영향
- 성능 저하

**P3 - 낮은 우선순위**
- 미관련 버그
- 작은 UI 문제
- 오타/스펠링 오류

### 버그 보고 절차

1. 이슈 등록 (GitHub Issues)
2. 재현 단계 확인
3. 영향 평가
4. 해결 일정 수립
5. 해결 후 배포
6. 이슈 닫기

## 마지막으로

이 체크리스트는 OPIc Helper의 품질 보증을 위한 가이드라인입니다.

**QA 원칙:**
1. 모든 기능을 체크리스트에 따라 테스트
2. 버그는 우선순위에 따라 분류하고 해결
3. 사용자 피드백을 적극 수집하고 반영
4. 지속적인 개선과 안정화

질문이나 제안사항이 있으면 GitHub Issues에 등록해주세요.
